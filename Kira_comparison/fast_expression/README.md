# Faster exact reductions with the existing seed model

This experiment measures a responsive Fermat shutdown in Kira's supplied-equation workflow. The stock interface waits one second before checking whether each Fermat child has exited. The isolated variant checks promptly, retains a one-second grace period, and forces termination only if its unreaped child remains alive. Symbolic arithmetic, seed-model weights and the 0.01 threshold remain unchanged.

Four methods compare the stock and modified Kira binaries with the full identity pool and the learned seed selection. All methods include cold process start, input loading, inference where used, exact reduction, failed attempts, fallback and coefficient verification. The same previously generated IBP pool supplies both methods; its original generation remains outside the measurement.

Development uses three original-training instances. The reserved experiment contains twelve instances in six original-test kinematic groups absent from all earlier box cost-test groups. Each method used five rotated repeats for one- and sixteen-target batches. Incomplete trials and skipped repeats remain in the results.

Scripts run in order: s00_prepare.py fixes cases and limits; s01_reap_child.h implements bounded child reaping; s02_reap_test.cpp checks normal and delayed exits, forced termination, invalid PIDs and already reaped children; s03_build.py builds an isolated binary and records a reproducible source patch; s04_build.sh schedules compilation. Later numbered scripts run and audit the paired measurements.

Tools and build logs remain under .tools/. The array began with two single-thread trials, increased to three after 95 records and later to six, with unchanged per-trial limits, each with 1.9 GB address space, 1.7 GB process-tree RSS and 32 MiB scratch. New retained records have a 12 MB cap; the combined storage bound reserves build artifacts, Git copies and the revised report below 10 GB.

## Measured results

The responsive Fermat shutdown comparison contains 480 planned records, 416 measured trials and 400 exact completions in twelve new held-out one-loop box instances. For one target, the modified learned workflow has a complete-time ratio of 0.384629 to the original learned workflow (descriptive 95% interval 0.342069–0.452551; 12 paired batches), with geometric mean times 5.528 and 2.126 seconds. For sixteen targets the corresponding ratio is 0.685856 (interval 0.540426–0.844099). Against the full pool with the same shutdown improvement, the single-target learned ratio is 0.690298 (interval 0.423691–0.931312). All completed reductions matched exact references. Both learned methods use the same original weights, threshold, early master check and fallback. The shutdown change preserves symbolic operations and also applies to the full-pool control. These measurements use existing IBP identity pools; they exclude their original generation.

Completion counts, paired medians, group-resampled intervals and failures appear in test_summary.json. test_validation.json independently checks raw exports, master coefficients, selected identities and model probabilities. Read trial records with s13_records.read_record; this restores losslessly shared arrays and verifies their SHA-256 hashes. Evidence text is stored in evidence/ by digest and is decoded with acceleration/s36_evidence.py after setting its HERE path to this folder. The shared/ directory avoids repeating large identical manifests, source lists, predictions and final coefficients across timing repeats.

## Running and checking the experiment

The original Kira remains at .tools/kira/bin/kira; the isolated modified executable is .tools/kira-fast-expression/kira. build.json identifies the exact upstream source commit, original and modified hashes, and compile/link commands. connect2kira.patch plus s01_reap_child.h reproduce the only source change. Compilation uses gcc/9.5.0 and the existing Kira dependencies. The patch and helper carry GPL-3.0-or-later licensing.

s05_worker.py runs the existing learned-seed or full-pool workflow with the selected binary. Its arguments are partition, case index, target count, policy, scratch directory and output JSON. The policies are stock_pool, stock_ml, exit_pool and exit_ml; use exit_ml for the measured faster learned workflow. s06_run.py wraps these calls in full-process time, memory and scratch limits and rotates their order. s07_development.sh runs the three development instances. s08_freeze.py fixes runtime code, both original model checkpoints, targets, identities, references and binaries. s09_test_array.sh schedules twelve cases with two batch sizes; s15_confirm.sh submits this array initially with at most two concurrent trials and then the independent audit. scheduler_amendment.json and scheduler_amendment_02.json record the increases to three and then six jobs. The final working storage bound is 9.970 GB, with a temporary 300 MB local allowance while the cluster comparisons run. Local report synchronization is deferred until those jobs finish, when the ordinary 400 MB publication allowance is restored. Frozen calculation code and individual trial limits stayed fixed.

s10_audit.py checks all retained results and verifies original/modified equation-input hashes, elimination counters and unchanged predictions. s11_summary.py reports paired costs and all completion outcomes; s12_check.sh schedules both operations. s13_records.py handles shared arrays. s14_report.py writes measured report text, a standalone PDF figure and figure_values.csv, taking the published data commit for the citation. s16_document.py updates the READMEs. s17_build_report.sh renders the final paper through s21_report_compat.py, which adapts two plotting calls to the installed Matplotlib API without changing the frozen source or results, with s20_report_finish.py stating the completed comparison cohorts and formatting the citation. s18_release.py verifies release readiness, and s19_finalize.sh schedules the final checks and documentation. Use fresh output directories when reproducing the released experiment; the runner refuses to overwrite existing trial records.

The full benchmark has five cold process repetitions per method and case; filesystem caches are not cleared. A failed measured repetition suppresses subsequent identical repetitions and leaves explicit skipped records. Timing ratios require five successes for each compared method. Samples resample entire kinematic groups 10,000 times; intervals describe the completed subset. Development retains two full-pool time-limit failures as well as its successful reductions. Compilation initially used the cluster's older default compiler; loading gcc/9.5.0 fixed that setup error. Both build logs remain outside Git history.
