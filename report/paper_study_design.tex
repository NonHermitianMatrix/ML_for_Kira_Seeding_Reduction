\section{How the project measures improvement}
\label{sec:design}
The study contains several workloads because the questions changed as the method developed. Constructed targets test whether learned decisions can recover known reductions. Native tests ask whether they save work when Kira must generate the equations. Exact-family tests ask how much algebra a proved identity can replace. We retain these distinctions when reporting the gains.

\subsection{Controls and timing boundaries}
A native control uses Kira's own choices with the same physical inputs and the stated seed bounds. A fixed control uses a strategy selected from development data, without request-dependent prediction. These controls share the surrounding implementation with the learned method. A comparison with an earlier project application instead measures the combined effect of changes to formulas, preparation, models, and execution. The restricted-vacuum cumulative test has its own original supplied-equation Kira control. It does not measure native generation of a general multiloop IBP system.

The reported time includes the operations inside each experiment's declared boundary, with all unsuccessful attempts and recovery included. The earliest supplied-equation test excludes construction of its stored identity pool. Native model tests include equation generation and exact elimination. Later complete-application tests also include process startup, loading, prediction, output, and cleanup. External reference preparation usually lies outside production time; the early native tests include coefficient comparisons, while the later application tests perform that audit outside the timer. The cumulative vacuum test includes output reading. These boundary differences remain part of the result, rather than being hidden in one global percentage.

Most native experiments use a prescribed master basis. Their times therefore concern subsequent reductions to that basis. We separately investigated basis discovery and compact preparation, retaining their costs. Offline training and the reductions used to produce training labels remain outside application timing. For example, the shared structural model required 9.5 seconds to fit after existing labels were collected; preparing and checking its 110-request reference grid required 1,056.4 and 772.2 seconds, including unsuccessful attempts. These costs matter when deciding how often a model or prepared basis must be reused.

\subsection{Independent examples and exact checks}
The constructed-data split groups related mass profiles across loop orders. Later native fits separate training, validation, and reserved parameter profiles or target batches. Some tests change parameters within known graph structures, while others exclude complete physical groups or loop orders from fitting and selection. A new parameter point does not constitute a new graph, and an independent product of many loops does not test a general connected graph at that loop order.

The reducer receives the family, targets, and required master indices, without the target's reference coefficients. Exact coefficient subtraction or polynomial cross multiplication checks the returned answer against an independently prepared reference in the same basis. Where bases differ, an exact conversion is required before equality can be asserted. Algebraic completion requires every requested target to reduce to the prescribed basis. Analytic paths additionally require their propagator and kinematic conditions, which are proved in the appendices and checked before substitution.

All failures remain in the coverage counts. Timing ratios over matched completions exclude unverified pairs and state how many pairs remain. In particular, the 43-request shared-model timing result comes from a 110-request grid, while the final 93-request serial comparison completes every requested output. A coordinate limit or a bounded reference failure does not prove that the corresponding integral is mathematically irreducible.

\subsection{Estimators and the meaning of a cumulative gain}
For paired methods, a time ratio below one means less elapsed time. We use either a ratio of summed request medians, an equal-group geometric mean of paired ratios, or the median time of one complete collection. Appendix~\ref{app:statistics} defines the current estimators; Appendix~\ref{app:project-estimators} derives the geometric and total-time forms used in the earlier comparisons. Every table identifies its estimator. Intervals retain the original experiment's paired bootstrap units, following Ref.~\cite{Efron1979}; repeated runs measure execution variation and do not create additional independent families.

A cumulative gain requires the original and final methods to be measured on identical requests with the same timing boundary. The eight-group vacuum comparison and the 75-request direct-vacuum-plus-reconstruction comparison satisfy this requirement for their respective stages. The subsequent 93-request comparison has a different population and preceding control. Multiplying their speed factors would describe no experiment that we performed.
